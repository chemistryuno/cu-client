## Why

当前项目仍然依赖 Go 后端提供认证、数据持久化、权限校验、房间管理、化学反应校验、实时通信与后台管理能力，而前端已经具备 Electron/Capacitor 运行环境与离线适配入口。将这些后端职责迁移到前端，可以把应用收敛为单端可运行架构，减少部署复杂度，并为离线优先、桌面端和移动端一致运行打下基础。

## What Changes

- 将现有通过 HTTP/WebSocket 暴露的后端业务能力迁移为前端内聚的客户端服务层，由前端直接承载认证状态、用户资料、房间状态、游戏流程与管理功能。
- 以浏览器或宿主环境中的本地存储能力替代服务端数据库访问，统一管理用户、卡组、反馈、公告、化学数据、历史记录与配置数据。
- 将房间、回合推进、出牌判定、化学反应校验、排行榜与积分结算等游戏域逻辑迁移到前端运行时。
- 将实时通信相关能力从依赖服务端 WebSocket Hub 调整为前端运行时内的会话同步机制；单机场景直接本地驱动，多端场景预留宿主桥接或点对点同步接口。
- 将管理员、协作者、普通用户权限判断从服务端中间件迁移到前端授权模型，并明确本次变更后的信任边界与数据保护限制。
- **BREAKING**：移除前端对现有 Go 后端 API 与后端静态部署链路的强依赖，前后端集成方式将从远程调用改为本地运行时调用。

## Capabilities

### New Capabilities
- `client-auth-and-session`: 在前端本地实现登录、会话、认证配置、账号安全状态与用户身份恢复。
- `client-data-runtime`: 在前端本地实现用户、卡组、反馈、公告、反应物、生成物、排行榜与系统配置的数据读写与持久化。
- `client-game-engine`: 在前端本地实现房间管理、对局流程、化学反应判定、积分结算、历史记录与回放能力。
- `client-admin-runtime`: 在前端本地实现管理员与协作者操作面所需的权限判定、配置管理、审核流与公告管理。

## Impact

- 前端代码：`frontend/src/utils/api.ts` 及其调用方将从远程 API 适配层演进为本地运行时服务层。
- 运行时架构：重点影响 Electron、Capacitor 和浏览器离线模式下的数据存储、状态同步与会话恢复方式。
- 后端代码：`backend/` 下 handlers、repository、middleware、game、websocket 等模块将不再是前端正常运行的前置依赖。
- 安全模型：认证、权限与敏感数据保护边界会发生变化，需要在设计中明确哪些能力仅适用于单机/受信宿主环境。
- 构建与发布：部署方式将从前后端协同部署转为以前端产物为主，可能影响现有 `copy-dist` 与静态资源集成流程。
