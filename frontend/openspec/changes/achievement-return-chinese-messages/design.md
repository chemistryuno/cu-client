## Context

当前项目已经有统一的本地化与双语文本基础，适合把“成就返回提示”从零散的硬编码文案收拢到集中管理的文案目录中。这个变更的核心不是改成就判定，而是让成就反馈在中文界面中更自然、更有层级感，并且在移动端仍然保持可读。

## Goals / Non-Goals

**Goals:**
- 提供一组可复用的中文成就返回文案。
- 让不同等级的成就反馈有明显的语气区分。
- 与现有本地化体系兼容，便于后续继续扩展中英双语。
- 保证提示内容简短、可读，不遮挡主界面内容。

**Non-Goals:**
- 不修改成就判定逻辑。
- 不重做成就系统的数据结构。
- 不引入新的外部依赖或新的后端接口。

## Decisions

1. 使用集中式文案目录承载成就返回消息，而不是把文案散落在页面组件里。
   - 这样可以统一语气、减少重复，并且方便后续继续补充其他成就场景。
   - 备选方案是在各个展示组件内直接写中文字符串，但这样会增加维护成本，也更容易出现风格不一致。

2. 将成就返回文案按层级拆分为普通达成、阶段里程碑、稀有成就、终局完成四类。
   - 这四类覆盖了大多数玩家最容易感知的成就反馈场景，也足够支撑“设计几个中文成就返回提示”的需求。
   - 备选方案是只提供单一模板，但会让所有成就反馈显得过于平铺，缺少激励感。

3. 文案内容以短句为主，必要时采用“标题 + 一句话说明”的结构。
   - 短句能避免在手机端挤压主玩法界面，也更适合通知式反馈。
   - 备选方案是长文本说明，但会降低回合中提示的可扫读性。

4. 预留英文键名与中文值的映射，后续可以直接复用现有双语组件或本地化解析器。
   - 这样当前需求可以先满足中文呈现，同时不会阻塞后续国际化。
   - 备选方案是只写中文硬编码，但后续再扩展会更碎片化。

## Risks / Trade-offs

- [Risk] 文案数量增加后可能出现重复或风格不统一 → 通过集中式目录和统一命名规范控制。
- [Risk] 手机端通知空间有限，长文案可能遮挡主要操作区 → 通过短句结构和顶部安全间距规避。
- [Risk] 仅中文呈现可能让双语模式下的显示策略不一致 → 保留键名和可扩展结构，后续可直接补英文对照。

## Migration Plan

1. 先在文案目录中加入成就返回中文模板和层级键值。
2. 再把成就提示的调用点切换到集中式文案读取。
3. 验证移动端与桌面端的显示长度，必要时微调提示文本。
4. 若回滚，只需恢复原先的硬编码或旧文案键名，不影响成就判定流程。

- 成就返回提示最终是否要走统一通知层，还是保留独立的成就展示卡片？
